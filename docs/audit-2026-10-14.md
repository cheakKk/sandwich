# Backend audit and review, 2026-10-14

An independent security audit and code review of `web/*.mjs`, run by two reviewing agents, then every finding traced and either fixed with a test or listed below as open. This is a first pass by automated reviewers; it does not replace the external penetration test the plan requires before any paying user.

## Fixed, with a test
- Duplicate workers from concurrent starts, and a delete racing a start leaving an orphan worker and files (`flow.test.mjs`, "two wakes at once").
- Worker lost model access after 12 hours (proxy token now slides with use; `limit.test.mjs`).
- Bomb and corrupt archives answered 502 and kept the sealed key; now every failed start deletes the session and its key (`flow.test.mjs`, "any failed start").
- `stop()` could give up on a live worker; now escalates to a hard kill and clears its timer. Spawn errors no longer crash the control plane. A dead worker is detected before the port check.
- Spend the ledger cannot price (server tools, remote MCP, containers, 1M-context and similar betas) is refused or stripped (`keyproxy.test.mjs`).
- The worker no longer inherits the operator's HOME, USERPROFILE or APPDATA (`hardening.test.mjs`).
- Dev sign-in refuses to exist next to real providers, not only in production.
- `.GIT`, `.git.`, `git~1` and `.gitmodules` are never imported (`importer.test.mjs`).
- Import decompression runs off the main thread; every import failure is an `ImportError`; response bodies are cancelled.
- Gateway: queued-message cap while a worker wakes, keepalive pings, pruned shared limiter, socket slot freed on raw close, hop-aware client IP (`proxyHops`), HSTS when secure.
- Gateway cookies: hosts 12 hours (was 30 days), guests 7 days; logging out or deleting an account ends them. An invite shown at the wrong address is no longer burned and leaves no ghost member.
- Account deletion removes the person's name from other sessions and re-checks for sessions created during the delete.
- Revocation: the drop call has a timeout and two retries and logs if unconfirmed.
- Input estimate for budget reservation is now conservative for dense text; streaming honours backpressure and decodes multi-byte text safely.
- Tests that proved less than they claimed were strengthened (second user in account deletion, non-empty scan, importer cap).

## Open (known, with where they land)
| Item | Why open | Lands in |
|---|---|---|
| The local driver is not a tenant boundary: one uid, shared loopback, other workers' environment readable on Linux | Needs real isolation | T16 container driver |
| A port can be taken between `freePort()` and the worker binding it; `reachable()` would then see the squatter | Dev driver only; fix is a readiness line from the child | T16 |
| Import runs inside the control plane process; a few slow imports can make others see "busy" | Needs a throwaway fetcher and a per-user queue | T16 |
| Proxy token is a bearer token, not bound to the sandbox's address, no in-flight cap per token | Needs the container network | T16 |
| A failed or aborted non-stream call is charged its full reservation | Deliberate (cannot know what was spent); revisit with provider usage reconciliation | before paying users |
| Revocation relies on the worker acknowledging the drop; the gateway does not close the sub's sockets itself | Small; do with the T14 session page work | T14 |
| Host entry token travels in `/_enter?t=` (single use, 60 seconds) | Switch to a POST handoff with the session page | T14 |
| No idle spin-down of workers; no per-session connection cap | Needs the container driver's lifecycle | T16 |
| Proxy and control plane share one database handle and process in dev; the private key must live only in a separate proxy service | Deployment | T17 |
| SECURITY.md still describes the single-process tool, not the hosted design | Rewrite after the container driver lands | before beta |
